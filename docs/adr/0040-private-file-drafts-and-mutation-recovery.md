# ADR 0040: Private file drafts and original mutation recovery

Status: Proposed, 2026-10-06. T07 implementation and final native regression pass; physically full isolated-volume acceptance is pending.

File drafts have a separate bounded contract from chat drafts. They include workspace, relative path, stable draft identity, editing revision, original text and disk version, current text, update time and an optional immutable original file mutation. A catalog CAS prevents one privileged Renderer from replacing another revision. Main stores the catalog using the existing initialized Windows OS cipher and a shared atomic private-file writer with flush before rename. It does not write workspace files or decide their business outcomes.

The current production path policy targets Windows workspace files. Main resolves authorized paths against the original canonical workspace root, returns relative canonical paths only, and rejects root retargeting, escaping aliases and multiply linked files. Existing paths retain actual filesystem case: two observed files in a case-sensitive directory have distinct editing owners. Existing directory aliases and case aliases resolve to the same canonical path. Only not-yet-existing suffixes use a Windows case-folded comparison namespace, so new-name variants share one draft until the first file exists, without rewriting the selected creation name. File Explorer resolves identity before mounting an editor; move resolves its destination before acquiring the existing mutation owner. Main validates new/transferred draft identities and detects two new aliases in the same catalog replacement. Restored unavailable sources remain private recovery copies. Actual temporary Windows filesystem tests cover directory junctions, ordinary case aliases and an enabled case-sensitive directory; Main IPC/native acceptance remains separate.

The implementation retains corrupted sources and disables writes after unreadable state or unknown disk failure. The protected catalog is limited to 32 file drafts, 256 KiB UTF-8 per current/original text and 32 MiB sealed storage. It has no silent plaintext fallback or dirty-draft eviction. Unit tests use an explicitly artificial cipher; OS encryption requires a separate actual Main gate.

The existing WorkspaceDocument authority remains the only workspace file mutation owner. The Renderer must persist a captured revision and original command ID before sending it. A definitive response settles only that captured edit, preserving newer content. A lost response retains the original envelope and baseline. The existing Runtime command journal retains completed save/move/delete metadata and the public protocol's fixed body-free rejection messages. It excludes read bodies and arbitrary I/O errors and retains its existing age/count limits. Expired receipts or truly unknown I/O outcomes cannot be converted into new writes. Reconciliation must use the original journal identity and actual version observations; equal visible text by itself does not establish that a particular command committed. It must not blindly rerun an uncertain save, move or delete.

The adapter is now attached to the one Feature Store and required root initialization. Recovery entries compare disk versions without writes, show original/draft/disk text after changes, and retain copyable missing/unavailable sources. An unsaved new-file copy can be explicitly created after a separate confirmation; an existing missing source cannot be silently recreated. Known save settlement preserves later edits and removes the original envelope only after private outcome acknowledgement. Move and delete retain their source until the private transfer/removal is acknowledged. Discard and move targets are leased during persistence so another view cannot overwrite a staged removal or transfer.

The native quit summary offers save/retain/discard/cancel before window destruction. The save-all user operation is bounded at 30 seconds; private flush retains its existing five-second barrier. Cancellation stops remaining batch operations and resumes editing. DraftQuitBlockedError belongs to the actual before-quit catch, where windows are retained; its earlier erroneous placement in the OAuth callback was removed. The original window producer remains responsible for all Dockview views and popouts.

Current verification: full App 95 files/440 tests, Node/Web/test types, App build, documents UI 26, architecture and released persistence contracts pass. The 26-check UI uses artificial storage/Core. A separate actual production Dockview/Main popout gate confirms the same draft ID, real Core save A/newer B and restoration of B to the parent after closing; the child has no privileged private draft API. Actual OS cipher/Core proves 32 saves, original command replay, late A/newer B, four physical quit choices and actual Main cuts. Actual external write/delete recovery preserves both copies and refuses unsafe writes. Windows sharing-denial of atomic rename preserves previous sealed bytes, retains copyable unprotected B, rejects false retain acknowledgement and recovers A after a real Main cut. Two ENOSPC injections and actual directory I/O failure are separately recorded; no physically full-volume claim. Final full Electron/Main regression passes 70 fixture requests/66 responses/four expected aborts/five Runtime kills, with no fatal or console errors. Runtime 152/1160 and current journal/owner 31 pass. Retain all intermediate failures. Only acknowledged protected edits can be promised after crashes.
