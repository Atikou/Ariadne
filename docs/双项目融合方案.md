# 双项目融合方案

## 当前结论

当前不融合。Ariadne 完整保留原桌面壳，外部功能项目不以源码、HTTP 服务或临时适配器接入。

原方案中的目录名称与当前目标目录按下面关系理解：

| 原目录 | 当前目录 | 处理方式 |
|---|---|---|
| `apps/desktop` | `app` | 完整保留桌面壳源码、模块、交互和测试，仅调整目录位置 |
| `serve` / `server` | `runtime` | 不迁移旧实现；当前只保留空目录，未来按独立子进程重新接入 |
| 无独立协议目录 | `packages/protocol` | 当前只保留空目录，正式接入 Runtime 时先建立稳定协议 |

因此“清理 Runtime/Server”只表示移除旧 HTTP/服务端接入，不表示删除 Chat、会话、Agent 状态、计划、工具输出、日志、权限等桌面模块。

## 未来推荐方式

如果桌面 app 与独立 Runtime 项目需要同时开发和发布，采用“协议包 + Runtime 发布物”的组合方式：

```text
app repository
  └─ depends on protocol version N

runtime repository
  └─ depends on protocol version N
     produces signed Runtime artifact

desktop release assembly
  └─ app artifact + compatible Runtime artifact
```

两个项目不互相导入 `src`，不复制数据库、模型、工具实现或内部类型。桌面发布流程只组合经过校验的 Runtime 构建产物。

## 所有权

| 范围 | app 项目 | Runtime 项目 |
|---|---|---|
| 页面、输入、用户确认 | 负责 | 不负责 |
| 文件选择、截图、剪贴板、通知、托盘、快捷键 | 负责 | 通过协议请求 |
| 进程启动、停止、异常检测 | 负责 | 提供可管理入口 |
| Agent、模型、记忆、工具、任务 | 不负责 | 负责 |
| 业务数据和迁移 | 不访问 | 负责 |
| 协议定义 | 共同评审 | 共同评审 |

## 开发联调

1. 协议变更先发布候选版本并通过兼容测试。
2. Runtime 独立构建，不依赖 Electron。
3. app 使用明确路径启动 Runtime 构建产物，通过子进程 IPC 握手。
4. 联调记录 app 版本、Runtime 版本、协议版本和构建校验值。
5. 不使用本地 HTTP 作为过渡层，也不让 app 直接运行 Runtime 源码仓库。

## 同时运行两个产品

如果 Runtime 项目还有自己的测试台或独立产品，两者必须使用不同进程和数据目录。Ariadne 只管理自己启动的 Runtime 实例，不接管另一产品的进程，也不共享可写数据库。

## 发布与回滚

- 发布清单锁定 app、Runtime 和 protocol 三个版本。
- 安装包校验 Runtime 产物签名或哈希。
- 升级前由 Runtime 完成数据兼容预检。
- 回滚只能回到仍可读取当前数据版本的 Runtime。
- 组合发布失败时保留干净桌面壳，不回退到 HTTP 或把业务逻辑塞入 Main。
